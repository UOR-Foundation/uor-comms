## Not proved

- **Convergence stated over permutations.** Neighbour exchanges generate every reordering, so any two orderings of the same events agree; that closing sentence is ordinary mathematics and not a theorem in the model, which has no notion of permutation.
- **That the kernel's answers are the modelled functions.** `RK-09` pins the text of the entry point and the vectors exercise it; no theorem relates `dispatch` to the decision functions, and none covers the byte readers `natAt` and `wordsFrom`.
- **That the host builds room state as the model does.** `Comms.State` defines the status and power of every member as a fold of the room's events, and each step of the fold is the kernel's own permission and membership answer. The kernel does not run the fold: a host must, and nothing checks that it does.
- **The fold over a set of events.** `Comms.State` folds a list in a given order. The place of each event in the order is proved to be the same on every peer that holds the same events, counted over ordering keys. That two different held events never share a place is proved (`heldEarlierEventIsPlacedFirst`), and the host folds by depth, then address, which `Comms.Fold` models: a parent is always folded before its event. Two things are not theorems: that the host's sorted list is the list of events by place, since no sorted list is built in the model; and so that `Comms.State` gives the same result on every peer. A place counts an event delivered twice twice; that a store keeps one copy per address is assumed. That applying an event twice changes nothing was tried and is not proved.
- **One byte form for every event.** The theorems cover one word, one list of words and pairs of addresses. That two different well-formed events never share bytes is not stated as one theorem, and that two ascending lists with the same addresses are equal is not proved.
- **Heads in general.** That every cited head stops being a head and every other head stays is proved for a room with one head only; the general statements were tried and are not proved.
- **Redaction over any history.** That a redaction stays in force is proved for the next redaction that arrives, not by induction over every later one; order and redelivery are proved for neighbours at the front of the list. The model does not check that the redactor sent the event ("own" is an input). The kernel answers who may redact, not what a redacted event shows.
- **Reading an event, in full.** The read-back theorems are about words, for an event laid out with four-word addresses. That `readable` accepts the words of every such event with a canonical form is not one theorem. The kernel reads the words from the request with `natAt` and refuses a length that is not whole words itself; neither step is proved, and nothing relates them to `decode`. A trailing byte is covered by a vector. Room, sender, device, target and content are four words by position; nothing else checks them.
- **That the host sends as the model does.** `Comms.Send` says when an event is composed and in what order it is signed, stored and announced. The kernel answers the order of the three steps and whether an event may be composed. It returns that answer, not the bytes. A redaction is asked through its own operation, which answers with `Comms.Redact::composes`; "own" is still an input the host supplies.
- **Creating a room, in full.** The theorems are about the creating event and the members it names. The room's address is the address of that event, which the host computes; that two rooms never share an address rests on BLAKE3. The kernel answers whether an event creates a room and whether the room is direct; it does not answer the status or power at creation, and `Comms.State` still takes the creator as an input, not from the event. A direct room is a room whose creating event names a target. Both parties hold the creator's power and a third member is never invited: the owner ruled on 2026-11-19 that a direct chat is exactly two people with equal standing. The target may be the creator, as notes to self. That a third member never joins is proved for invitation only; a direct room is closed, so nobody joins uninvited while room settings are fixed. That two parties never get two direct rooms is not modelled: the host reuses one it already holds (`findDirect`), and two created at the same moment both stand.
- **Requests the page types as text.** The browser replay types a request that is valid UTF-8 as text, and a text field turns a carriage return into a line feed, so no vector may be valid UTF-8 and hold byte 0x0d. Every content vector carries a sent time whose bytes are not valid UTF-8, and the one-byte request `0d`, a lone carriage return, is not a vector.
- **How many vectors fit.** The acceptance vectors are one literal list in the application record, which prismpm requires to be closed, and the checker and prismpm's snapshot refuse one nested past their recursion limit: 87 passed the gate, 115 did not, and 105 are kept. Each operation keeps one vector per distinct answer; a wrong length is tested for three operations, not every one. New operations get one vector per distinct answer and boundary, and one wrong-length vector where the operation is new.
- **The approved CEWP proposals, in full.** The relay tree's fan-out is fixed at four and the call's mesh limit at six: the prover's arithmetic is linear, so neither can be a variable divisor or bound, and six is a guess to be measured. The host orders members for the tree by place and divides the receiver's budget by the number of senders; neither step is in the model. Meeting topics are derived by the host with BLAKE3 `derive_key` over the epoch secret and the hour; the model decides only who holds an epoch's topic. That a peer in fact forwards or holds mail as answered is not checked. The queue is proved equal to the permission rule with the direct-room rule; composing an event adds only its canonical form (`Comms.Send::mayCompose`), which concerns the event, not the person.
- **Message content, in full.** The theorems are about the field rule and the byte scans. That `valid` reads the fields from the places the layout puts them, that decoding undoes encoding, and that two different valid contents never share bytes are not theorems. Mentions are compared as four 64-bit words each with `Comms.Event::ascending`. UTF-8 well-formedness and Unicode normal form are not checked: the host normalises to NFC when it encodes, and nothing proves it. An edit's sender and attachments, and repeated reactions, are rules of aggregation, which is not modelled. The kernel takes requests up to 5,748 bytes, the largest valid content with its operation byte, and may allocate 32 KiB. Reading content costs about 4.3 allocated bytes per content byte (the guest trapped at about 480 bytes when it could allocate 2,048), so text is limited to 4,096 bytes: an allocation bound of 128 KiB, which would allow 16,384, makes the gate's Lean build exceed its recursion depth on the boundary vector prismpm requires. The first content vector carries 2,000 bytes of text, and a host test sends the largest content.** The required power and whether the room is open are fixed for the fold. Events that change them, and a required power per action, are not modelled.
- **The ban race.** A ban and an event from the banned member that do not see each other are settled by rank; the security argument is not proved.
- **The planted-defect check** was run in a scaffold before this repository existed, not through this gate.

## Assumed

- BLAKE3 is collision resistant and the host computes it correctly. The kernel is told two addresses to compare; it does not hash.
- Signatures cannot be forged and the host checks them correctly.
- Prism ID's verdict on a device is correct. The kernel takes it as a flag and restates none of stitch's model.
- Encryption hides content from anyone without the epoch key.
- The network eventually delivers every event to every member.

## Not done

- The host in `host/` is a first slice, tested in the gate (`just host`, part of `just vv`) against the holo the same run builds: two peers in one process create a direct room, join, send, receive, hold events that arrive early, agree on one order, and refuse a tampered event, a wrong address, a device of another identity and a banned member. Events and content survive a reload in the browser store (IndexedDB), and an engine rebuilds its rooms from it by admitting every kept event again; nothing crosses a network, nothing is encrypted, and Prism ID is not wired: the caller supplies the signer, the device verdict and the transport. The host computes three rules instead of asking: an event's depth (the rule is `Comms.Fold::depthOf`, proved; that the host's code matches it is not), a member's standing at creation, and the power a change of power leaves. `host/README.md` lists the rest. Receiving and reading an event into fields are done by the host and are not modelled.
- Knock, space-restricted joins, reporting, presence, per-user synced data and profiles are not in the model.
- Hosted-prover runs made while developing are diagnostics; only the build workflow's run is cited above.
